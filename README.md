# Enhanced-index

浏览器视频筛选扩展。当前首版支持 **B 站的综合搜索页和视频搜索页**；不需要提前进入 options.html 设置。

## 怎么用

1. 在 Chrome 的扩展管理页或 Edge 的扩展管理页开启“开发者模式”。
2. 点击“加载已解压的扩展”，选择本项目文件夹。
3. 已加载过扩展时，点击扩展的“重新加载”，再刷新 B 站网页。
4. 点击搜索栏旁的艾绿色圆形按钮，填写时长、播放量范围，再点击“应用筛选”。
5. 点击“恢复全部”清除条件并还原卡片。Esc 或点击窗口外可关闭面板。

时长可以填 `00:00～10:00`（分:秒），也可填 `01:00:00`（时:分:秒）。上下限分别填写，空白表示不限。
播放量支持 `10000`、`1.2万`、`2亿` 等格式。上下限都包含边界值。
条件保存到浏览器本地，下次搜索可继续使用。首页或视频播放页也能填写条件，但只在综合 / 视频搜索结果页过滤。

## 当前支持范围

- 按卡片显示的时长和播放量过滤；保留 B 站原有顺序，不移动网站卡片。
- 支持翻页、换关键词、懒加载、卡片内容更新；不会替用户自动翻页。
- 隐藏的是视频对应的网格位置，因此正常情况下不会留下空白格。
- 默认保留需要筛选的信息缺失的视频；取消对应复选框后，这类视频不参与匹配。
- 只读取带有普通视频链接的卡片，不处理直播、用户、番剧或没有识别出视频 ID 的内容。
- **最高画质暂未实现**：面板中明确禁用此项。不会从标题“4K”、封面尺寸或当前播放画质推断最高画质。
- **YouTube 尚未实现**。欢迎页里的 YouTube 链接不是已支持筛选的声明。
- 只处理网页已经加载的卡片，不代表筛选了整个平台。多 P 视频按搜索卡片显示的时长处理。
- 卡片的“1.2万”按 12000 比较，无法还原其精确播放量。
- 网站可能更新 DOM；届时主要维护数据读取器和搜索框定位规则。

## 每个文件做什么

| 文件 | 职责 |
| --- | --- |
| `manifest.json` | 扩展入口；指定只在 B 站加载下列脚本和样式，声明本地存储权限。 |
| `bilibili-data.js` | 数据读取器：把时间和播放量文字换成数字；读取视频 ID；检查条件是否合法、视频是否符合条件。 |
| `bilibili-content.js` | 页面交互：圆形按钮、下拉面板、卡片显隐、动态页面监听、条件保存。 |
| `bilibili-content.css` | 按钮与面板样式，以及隐藏卡片所用的规则。 |
| `background.js` | 保留原有的安装后打开欢迎页逻辑；本版不需要后台获取视频数据。 |
| `options.html` / `options.css` / `option.js` | 原有欢迎页，与视频筛选条件无关。 |

### 数据是怎么流动的

用户在下拉面板填写条件 → `validateSettings()` 校验并换算成数字 → `readCard()` 读取卡片 → `evaluateVideo()` 判断 → 页面脚本显示或隐藏该卡片。

主要看这些函数：
- `parseDuration("08:25")` 得到 505 秒。
- `parseViews("1.2万")` 得到 12000。
- `readCard(card)` 得到视频 ID、时长、播放量；读不到的字段为 null。
- `scanCards()` 在应用条件或页面更新后重新处理当前卡片。
- `findAnchor()` 找搜索框，`positionUI()` 把圆形按钮与面板放在它旁边。

## 权限与数据

仅申请 B 站两类页面的脚本访问范围，以及 `storage` 权限。
不读取 Cookie、不上传浏览记录、不调用视频接口。保存的只有四个范围输入值和一个“保留信息不全视频”开关。
网站访问权限需要浏览器授权；若按钮不出现，先检查扩展是否允许访问 B 站，再刷新页面。

## 开发检查

运行扩展本身不需要 Node.js。开发者如有 Node.js，可在项目目录运行：

```sh
node --test tests/bilibili-data.test.cjs
```

测试覆盖时间/播放量换算、无效输入、边界值、未知值处理。
